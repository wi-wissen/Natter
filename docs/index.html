Natter, a small Python for the classroom

A Python interpreter written in JavaScript. It loads fast, has a debugger built in, and an endless loop never freezes the page. Made for teaching.

Packaged for embedding as @natterjs/core, @natterjs/web and @natterjs/assets on npm, MIT licensed. Everything on this page is marked as in the base planned or not planned.

01 · Why

Why another Python?

Browser Python normally means shipping a large runtime. Natter is a compact interpreter that implements the part of Python taught in school, and implements it so that the things teachers need are easy.

  • ~38 KB

    Small start

    The core starts at about 38 KB gzipped. Modules such as re, numpy, forms or Pygame Zero load only when a program imports them (15 to 40 KB each).

  • while True:

    Never freezes

    Programs run in slices with an instruction budget. An endless loop stops and shows the line it is on.

  • step("over")

    Debugger included

    Breakpoints, step into, over and out, variables and call stack. No patched runtime needed.

  • Did you mean…?

    Friendly errors

    Messages in English and German with hints such as “Did you mean…?”, in the style of CPython 3.12.

  • seed: 42

    Reproducible

    Optional fixed random seed and platform-independent math, so every student sees the same output.

  • == CPython

    Real Python

    Code is valid Python. What runs here should run in CPython, and the test suite compares both.

02 · Inside

How it works

  1. Source
  2. Lexer
  3. Parser
  4. Compiler
  5. Bytecode VM
A stack machine with its own frame stack
It does not use JavaScript recursion, so it can stop and resume after any instruction.
Budgeted execution
run(task, n) executes at most n instructions, then hands control back to the page.
Suspend and resume
A native function such as input() or an animated forward(100) can park the program and continue it later. Blocking calls look like normal Python.
Tasks
The main program, every event handler and every frame of a game loop are separate tasks with their own budget.
Host bridge
Modules (turtle, games, forms, plots) talk to the VM through host objects. The core knows nothing about the DOM.
Debugger
The compiler marks statement starts. The VM checks breakpoints and step mode there and can report variables and the call stack at any pause.

03 · Language

The language

A subset of Python 3 that behaves like Python and prints the same output. The aim is the part used in schools, documented exactly.

AreaContentsStatus
BasicsIntegers of any size, floats, strings with f-strings and format, lists, tuples, dicts, slices, if/elif/else, while, for with else, break, continue, pass, tuple swap a, b = b, ain the base
Functionsdef with defaults, *args, **kwargs, closures, global, nonlocal, lambda, decorators, unpacking, del, assertin the base
ComprehensionsList and dict comprehensionsin the base
Classesclass, __init__, inheritance, super(), __str__, __repr__, @property, operator methods such as __add__in the base
Exceptionstry/except/else/finally, raise, custom exception classesin the base
Sets, generatorsset, frozenset, yield, lazy generator expressionsin the base
Inputinput() (the page waits for the answer), with and context managers, sys.exit(), print(file=…)in the base
Filesopen() with read, write and append, os and os.path, import of your own files. The project lives in memory; the host keeps it where it likes (folder, ZIP, browser storage)in the base
Type hintsParsed and ignored, so code from books runsin the base
Threads, async, eval, execNot useful in a classroom and hard to make safenot planned

Errors carry the line, a call stack and a hint. Numbers behave like CPython: integers become big integers above 253, round() uses banker's rounding, // and % follow CPython.

05 · Determinism

Same program, same output

IEEE 754

Same math everywhere

Addition, multiplication and sqrt are exact IEEE 754. Functions that browsers round differently, like sin and exp, are implemented inside Natter so results are identical on every device.

seed

Random seed

The seed is an optional parameter. Without it, the seed comes from the browser's secure randomness and every run differs, as in normal Python. With it, every run is the same. The seed that was used can be shown to reproduce a run.

1000

Limits

Recursion depth 1000 like CPython, fixed limits for list and string size, independent of the browser's JavaScript stack.

06 · Embedding

Embedding

The browser host @natterjs/web runs a program in a page: time slices so a loop never freezes it, console, turtle, Kara, Pygame Zero, forms, plots and the debugger. Heavy parts load only when imported. The core alone is @natterjs/core (Node and browser), the images and sounds are @natterjs/assets (CC0).

in the base

# with a bundler (Vite, esbuild, webpack)
npm install @natterjs/web
# optional: the image and sound library
npm install @natterjs/assets
import { createRunner, createConsole } from "@natterjs/web";
// no build step? Import the same from jsDelivr:
// "https://cdn.jsdelivr.net/npm/@natterjs/web@0.1.0/dist/natter-web.js"

const runner = createRunner();
createConsole(document.querySelector("#console")).connect(runner);

await runner.run(`
for i in range(3):
    print("Hello", i)
`, { seed: 42 });
// runner.pause(), runner.step("over"), runner.inspect(), runner.stop()
// Node 18+: npm install @natterjs/core
import { runToEnd } from "@natterjs/core";
console.log(runToEnd("print(1 + 1)").output);   // 2

Images for Pygame Zero and Kara: createPgzero(el, { assets: { baseUrl: "https://cdn.jsdelivr.net/npm/@natterjs/assets@0.1.0/", catalog: "catalog.json" } }). Self-hosting: copy the whole dist/ folder (the start file loads its chunks from next to itself). Each GitHub release also has natter-web-<version>.zip and the npm tarballs (npm install https://github.com/wi-wissen/Natter/releases/download/v0.1.0/natterjs-web-0.1.0.tgz), with checksums.
